# agency 개편: 주인이 읽을 요약

agency 문서를 새 구조로 다시 썼습니다. 코드는 아직 그대로이고, 이 문서를 읽고 정한 뒤 2단계(저장소·정책·API·프롬프트·도구 이전)와 3단계(콘솔)로 갑니다. 영어 정본은 `docs/agents.md`, `docs/supervisors.md`, `docs/agent-roles.md`, `docs/repositories.md`, `docs/provider-order.md`, `docs/role-slots.md`입니다.

## 쓰는 법에서 바뀌는 것

- **축은 둘뿐입니다.** 감독관(방을 가지고 사람과 말하는 쪽)과 역할(일을 실행하는 모든 것). 저장소는 일하는 장소일 뿐 에이전트가 아닙니다. 어떤 역할이든 어떤 저장소 경로에서든 돌 수 있습니다.
- **역할의 제공자 순서:** 역할 탭에서 역할마다 제공자를 위에서부터 순서대로 놓고, 각 제공자 칸에 그 제공자에서 쓸 모델과 노력 수준을 고릅니다. 한 제공자는 한 번만 들어갑니다(제공자마다 쿼터가 하나라서). 남은 쿼터 기준선(기본 1%)도 같은 화면에서 정합니다.
- **돌아가는 규칙:** 실행은 순서의 첫 제공자 중 남은 쿼터가 기준선보다 많은 곳에서 나갑니다. Claude Code·Codex는 5시간·주간 창 중 덜 남은 쪽, DeepSeek은 잔액, 등록 모델은 늘 쿼터 있음으로 봅니다. 실패나 한도면 다음 제공자로, 다음 실행은 다시 첫 제공자부터. 전부 바닥이면 거절하지 않고 기다립니다.
- **역할의 동시 실행 수:** 역할 탭의 "최대 동시 실행"이 곧 그 역할의 칸 수입니다. 제공자별 동시 제한은 없습니다. 예: worker를 2로 두면 저장소 세 곳의 작업이 둘씩 돌고 셋째는 기다립니다.
- **세션:** 역할 × 경로 × 제공자/모델이 같고 캐시 수명 안이면 이어 쓰고, 아니면 새로 엽니다. 역할마다 상주 창은 없고, 일이 오면 창을 띄우고 끝나면 닫습니다.
- **저장소 고정 모델:** 저장소가 모델을 고정하면 그 저장소 작업은 그 모델로만 돕니다. 쓸 수 없으면 다른 모델로 넘기지 않고 기다립니다.
- **작업의 역할:** 항목은 기본이 `worker`이고, 항목마다 어떤 역할이든 고를 수 있습니다.
- **위임:** 감독관은 어떤 역할에든 맡길 수 있고(기본 helper), 기본으로는 감독관 자신의 제공자·모델로 도는 분신입니다. 없는 역할 이름은 오류입니다.
- **캐시 데우기:** 감독관만, 감독관 화면에서 제공자별로 켜고 끕니다. 역할·저장소·작업 칸은 데우지 않습니다.

## 콘솔 탭

- **감독관 / 역할 / 저장소 / 등록 모델 / 모델 파일** 다섯 개. 일반 탭은 없어집니다.
- 감독관 화면: 제공자 순서, 제공자별 데우기, 압축 기준, 초안 질문.
- 역할 화면: 프롬프트, 도구 묶음, 제공자 순서, 동시 실행 수, 세션 유지/새로, 압축 기준, 그리고 일반 탭의 세션 목록 대신 **역할별 세션 기록**.
- 감독관 화면 표의 열 너비 조절과 처음 열 너비 문제는 3단계에서 UX 규칙대로 고칩니다.

## 잃는 것과 얻는 것

- **잃는 것:** 등급(Supervisor/Frontier/Reliable/Fine/Light/Simple)과 등급 표, `role:<이름>` 키와 작업 키, 전역 제공자 순서, 작업 키별 경로·계정·등록 모델 지정, 공용 협업자 풀의 등급별 용량 표, 제공자·등급별 압축 비율 표, 전역 데우기 스위치, worker별 데우기 스위치와 일시 정지, 보조 작업자 데우기 수, 일반 탭(세션 목록, 기본 프롬프트 선택, 에이전트별 설정), 게이트 행과 게이트 역할.
- **얻는 것:** 역할 하나만 보면 어디서 무엇으로 몇 개가 도는지 다 보입니다. 쿼터가 바닥나면 제공자를 스스로 갈아타고, 다 바닥이면 거절 대신 기다립니다. 저장소를 늘려도 상주 창과 데우기 비용이 늘지 않습니다.

## 지금 행이 무엇이 되는지

- **worker 역할 행 54개 → 저장소 행 53개.** 그중 하나(웹 콘솔의 보조 작업자)는 행이 아니라 웹 저장소의 보조 체크아웃 수 1이 됩니다. 외부 저장소도 모두 저장소 행입니다. video 저장소를 더하면 저장소는 54개로, 말씀하신 40개보다 많습니다.
- **고정 모델:** worker 행 47개가 DeepSeek flash에 고정돼 있습니다. 이걸 저장소 고정으로 옮기면 DeepSeek 잔액이 바닥날 때 47곳이 전부 멈춥니다. 그래서 worker 역할의 첫 제공자를 DeepSeek flash로 두고, 저장소 고정은 등록 모델에 일부러 고정한 2곳만 옮기기를 권합니다.
- **helper 행 → helper 역할**(첫 제공자 Claude Code, 지금 고정 모델 그대로). **video 행 → video 역할 + video 저장소 행.**
- **검색 행 → searcher 역할, 브라우즈 행 → browser 역할, 번역 행 → translator 역할.** transliterator 역할은 이미 있고 그대로 갑니다.
- **협업자 역할 builder·verifier·digest·scout·screener → 역할 행.** 각 역할의 순서는 지금 그 역할 등급이 제공자마다 가리키는 모델을 전역 순서대로 늘어놓은 것으로 만듭니다.
- **채팅 행 2개 → 감독관 2개.** 기본 응답자는 지금 경로(DeepSeek부터 전역 순서)를 순서로, 동반 감독관은 고정 등록 모델 하나를 순서로.
- **게이트 행 2개와 gate 역할 → 은퇴.** upkeep 역할은 남습니다.
- **풀 용량 표 → 버림.** 협업자 역할의 동시 실행 수는 지금 첫 제공자의 등급 한도(digest·verifier 6, scout·screener 12)로 시작합니다.
- **압축 비율 표 → 행마다 하나.** 각 감독관·역할은 지금 자기 제공자·등급 칸의 값을 가져갑니다.
